## 1. 배경과 목적

낚시냥(Fishing Cat)은 브라우저에서 동작하는 세로형 픽셀 아케이드 게임이다. 이 게임을 **재작성하지 않고** Flutter WebView로 감싸서 **Google Play와 App Store에 동시 출시**한다.

냥냥 러너에서 검증된 방식(오프라인 자산 번들 + localhost 서빙 + JS→Flutter 단일 브리지)을 그대로 따른다. Flame 등 네이티브 게임 엔진으로 다시 만드는 방안은 비용 대비 이득이 없어 범위에서 제외한다.

## 2. 게임 개요

### 2.1 한 줄 소개

샴 고양이(샴냥이)를 **좌·중·우 3개 레인**으로 움직여, 펭귄들이 낚아 올려 위에서 떨어뜨리는 물고기를 받아먹고 쓰레기와 위험한 바다 생물은 피하는 **60초 스테이지형 세로 아케이드 게임**이다.

### 2.2 화면과 해상도

- 기준 해상도 **640×1024 (세로)**. 화면 크기에 맞춰 비율을 유지한 채 확대·축소(`fit`)하고, 남는 영역은 배경색으로 둔다.
- 픽셀 아트 스프라이트에 수채화 배경을 쓰고, 글꼴은 **Galmuri11/Galmuri9** 픽셀 글꼴(현재 CDN에서 로드)을 쓴다.

### 2.3 화면 흐름

```
타이틀 ──START──▶ 스테이지 안내 ──시작!──▶ READY → GO! ──▶ 플레이
  ▲  └─…─▶ 크레딧(닫기)                                    │ ⏸
  │                                                        ├─▶ 일시정지 ─▶ 계속하기 / 처음으로
  │                                                        ▼
  └────────── 처음으로 ◀────── 결과 (STAGE CLEAR / TIME UP / GAME OVER / ALL CLEAR!)
                                 ├─ 다음 스테이지 → 다음 스테이지 안내
                                 ├─ 다시 도전 → 같은 스테이지 안내 (점수는 스테이지 시작 시점으로, 생명 3개로 복구)
                                 └─ 다시 하기 (ALL CLEAR 후) → 1스테이지부터
```

| 화면 | 내용 |
|---|---|
| 타이틀 | 로고, 최고 점수(BEST), START, 사운드 토글(♪/✕), 크레딧 |
| 크레딧 | PLAN: Tony, Griffin / PROGRAM: Tony / DESIGN: Griffin |
| 스테이지 안내 | 스테이지 번호·장소명, 목표 점수, 제한시간 60초, 등장 아이템 목록(처음 나오는 아이템에 `NEW` 표시) |
| 플레이 HUD | 점수, 하트(최대 3), 일시정지 버튼, 남은 시간 바(10초 이하 경고), FEVER 게이지, 스테이지/목표 진행도 |
| 일시정지 | 계속하기 / 처음으로 |
| 결과 | 제목, 별(0~3), 결과별 고양이 이미지, 스테이지 점수·총 점수·최고 점수, 다음 행동 버튼 |

### 2.4 조작

- **이동**: 화면 좌·우 화살표 버튼(터치). 데스크톱은 방향키 또는 A·D.
- **일시정지**: HUD의 일시정지 버튼. 데스크톱은 Esc 또는 P.
- 레인을 옮기는 순간에도 해당 레인에서 받을 수 있는 아이템이 있으면 바로 받는다.

### 2.5 핵심 규칙

| 항목 | 규칙 |
|---|---|
| 제한시간 | 스테이지마다 60초. 시간이 끝나면 스테이지가 종료된다 |
| 생명 | 최대 3개. 위험 생물에 맞으면 1개를 잃고, 0이 되면 GAME OVER |
| 피격 후 보호 | 맞은 뒤 1.2초간 무적(이때 받는 위험 생물은 "휴~") |
| 클리어 조건 | 시간 종료 시점에 **그 스테이지에서 얻은 점수 ≥ 목표 점수** |
| 이어지는 값 | 총 점수와 남은 생명은 다음 스테이지로 이어진다 |
| 별 | 목표의 1.8배 이상 3개, 1.35배 이상 2개, 클리어 시 최소 1개 |
| 최고 점수 | 총 점수 기준으로 저장 (`localStorage: fc_best`) |
| 사운드 설정 | Web Audio 합성 효과음, 켜기/끄기 저장 (`localStorage: fc_sound`) |

### 2.6 아이템

| 종류 | 효과 |
|---|---|
| 물고기 (20종) | 점수 획득(+100 ~ +1200). 받으면 고양이가 그 물고기를 들고 기뻐하며 FEVER 게이지 +1 |
| 쓰레기 (빈 캔·헌 장화) | 점수 -100, FEVER 게이지 -1 |
| 생명 하트 | 생명 +1 (생명이 가득하면 +300점). 생명이 가득할 때는 나오지 않음 |
| 위험 생물 (폭탄·상어·해파리·성게·쏠배감펭·집게 게·전기뱀장어·가오리·가시복·문어·바닷가재·톱가오리) | 생명 -1, FEVER 게이지 -1. 폭탄을 제외한 위험 생물은 떨어지기 전에 해당 레인에 `!` 경고를 띄운다. 폭탄은 폭발 연출과 함께 고양이가 약 1.2초간 그을린 모습이 된다 |

### 2.7 FEVER

- 피버가 아닐 때 물고기를 **18마리** 받으면 **7초간 FEVER**가 발동한다.
- 발동 즉시 화면의 위험 생물과 쓰레기가 모두 사라지고, 그 스테이지의 물고기만 모든 레인에 비처럼 쏟아진다.
- FEVER 중 물고기 점수는 **2배**다.

### 2.8 스테이지 구성 (총 30단계)

- 1스테이지 목표 3,500점에서 30스테이지 50,000점까지 오른다.
- 낙하 속도는 330 → 750, 생성 간격은 0.85초 → 0.30초로 점점 빨라지고, 한 스테이지 안에서도 시간이 갈수록 생성 간격이 최대 28% 줄어든다.
- 스테이지마다 새 물고기나 새 위험 생물이 하나씩 나오고, 장소에 맞는 수채화 배경과 테마(낮·노을·밤)를 쓴다.
- 30스테이지를 클리어하면 `ALL CLEAR!`.
- 스테이지별 상세 데이터(장소명, 목표, 신규 아이템)는 게임 원본의 `README.md` 스테이지 표를 기준으로 한다.

### 2.9 현재 원본의 테스트 설정

원본은 `TEST_MODE = true` 상태다. 생명이 줄지 않고, 목표 점수에 못 미쳐도 시간이 끝나면 클리어된다. HUD에는 "테스트 모드" 라벨이 표시된다. **앱 출시본은 일반 모드로 출시한다** (3장 참고).

## 3. 핵심 결정 사항

| 항목 | 결정 |
|---|---|
| 전환 방식 | Flutter WebView 래핑 (`flutter_inappwebview`), 게임 자산은 오프라인 번들 |
| 서빙 방식 | 번들 자산을 고정 포트의 localhost로 서빙한다. iOS에서 `file://`로 열면 localStorage가 유지된다는 보장이 없기 때문이다. 포트는 origin의 일부이므로 출시 후에는 바꾸지 않는다 |
| 플랫폼 | Android + iOS 동시 출시 |
| 앱 이름 / 번들 ID | **낚시냥** / `com.mocadev.catfishing` (두 플랫폼 동일) |
| 화면 | **세로(portrait) 고정** + 몰입 전체화면. 노치·홈 인디케이터 영역은 레터박스로 둔다 |
| 게임 모드 | **출시본은 일반 모드** (TEST_MODE 꺼짐, "테스트 모드" 라벨 미표시) |
| 수익화 | **1차 출시는 광고 없음.** 브리지만 광고 이벤트를 추가할 수 있는 구조로 둔다 |
| 세이브 | localStorage 유지 (`fc_best`, `fc_sound`). 네이티브로 옮기지 않는다 |
| 게임 원본 관리 | 이 저장소 안에 게임 실행 파일을 두고 이를 앱 쪽 유일 원본으로 삼는다. 빌드 전에 동기화 스크립트로 앱 assets에 복사한다 (냥냥 러너와 같은 방식). 개발 자료(테스트, 스크린샷, 프롬프트, 백업, raw 이미지, 디자인 인계 폴더)는 가져오지 않는다 |
| 이미지 용량 | **원본은 건드리지 않고, 앱에 들어가는 사본만 압축한다.** 현재 배경 30장 약 89MB, 스프라이트 약 29MB로 대부분 장당 1~3MB다. 게임 기준 해상도에 맞게 줄여 앱 크기를 낮추되, 게임이 참조하는 경로가 깨지면 안 된다 |
| 글꼴 | Galmuri 글꼴을 앱에 포함해 오프라인에서도 픽셀 글꼴이 보이게 한다 |
| 네이티브 요소 (1차) | 햅틱 진동, 결과 화면 점수 공유. Apple 심사 가이드라인 4.2(단순 웹 래핑 거절)에 대비해 미리 넣는다 |
| 아이콘 / 스플래시 | 기존 고양이 이미지 기반으로 제작 (1024×1024 포함) |

## 4. 설계 원칙

1. **게임 원본을 망가뜨리지 않는다**: 게임 JS에 추가하는 브리지 호출(화면 전환, 햅틱, 공유)은 모두 `window.NativeBridge` 존재 확인으로 감싼다. 원본을 브라우저에서 열면 지금과 똑같이 동작해야 한다.
2. **오프라인에서 모든 기능이 동작한다**: HTML·JS·CSS·이미지·글꼴을 전부 앱에 넣는다. 네트워크 없이 모든 기능이 동작해야 한다.
3. **브리지는 통로 하나로 만든다**: JS→Flutter 이벤트는 `NativeBridge.send(type, payload)` 하나로 보내고, Flutter→JS 호출은 게임이 노출하는 `GameControl` 객체로 한다. 이벤트를 추가할 때 통로 자체는 고치지 않는다.
4. **프로젝트 규칙을 따른다**: Flutter 쪽 코드는 이 저장소의 `CLAUDE.md` 구조(features / shared / core)와 Riverpod 규칙을 따른다.

## 5. 플랫폼별 동작 요구

- **공통**
  - 앱이 백그라운드로 가면 플레이 중인 게임은 일시정지 화면으로 바뀐다. 게임이 이미 `visibilitychange`를 처리하므로 WebView에서 이 이벤트가 실제로 오는지 확인하고, 안 오면 앱 생명주기로 보완한다.
  - 게임 페이지가 다 그려질 때까지 네이티브 스플래시를 유지해 빈 화면이 보이지 않게 한다.
  - 확대·축소와 스크롤, 오버스크롤 바운스를 막는다.
- **Android**
  - 뒤로가기: 플레이 중에는 게임을 멈춘 채 종료 확인 창을 띄우고, 취소하면 바로 이어서 한다. 그 밖의 화면에서는 바로 종료 확인 창을 띄운다.
  - Android 15+(targetSdk 35+)에서도 몰입 전체화면이 유지돼야 한다.
- **iOS**
  - WKWebView에서 첫 터치 뒤 효과음(Web Audio)이 나와야 한다. 게임이 START 버튼에서 오디오를 깨우므로 WebView 미디어 설정만 맞추면 된다.
