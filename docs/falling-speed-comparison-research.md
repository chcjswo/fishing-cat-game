## 화면이 길어졌을 때의 해석

아래는 외부 게임에 대한 측정치가 아니라 일정한 수직 속도라는 조건에서 도출한 계산이다.

- 이동 거리 D, 속도 v이면 도착 시간은 T = D / v다. 이동 거리가 25% 늘고 속도가 같다면 도착 시간도 25% 늘어난다.
- 한 화면을 가로지르는 비율은 v / D다. 위 상황에서는 기존의 80%로 줄어 더 느리게 보일 수 있다.
- 기존 도착 시간을 복원하는 속도는 `기존 속도 × 새 이동 거리 / 기존 이동 거리`다. 이 값은 화면 전체 높이보다 실제 생성 지점에서 포획/충돌 지점까지의 거리를 기준으로 구하는 것이 맞다.
- 생성 간격이 유지되면 정상 상태의 도착 간격도 유지된다. 다만 시작 후 첫 포획까지의 대기, 개체의 체류 시간, 화면 내 개체 수는 증가할 수 있다. 따라서 긴 화면이 모든 의미에서 이벤트 빈도를 낮췄다고 단정하면 안 된다.

추천 판단: 기기별 생성→포획 도착 시간 보정의 적용 여부를 확인하고, 그다음 단계별 가속과 생성 간격을 각각 튜닝한다. 이는 조사 사례와 거리/시간 관계를 바탕으로 한 설계 제안이며, 다른 게임의 검증된 정답 수치는 아니다.

도달 시간은 기본 높이 1024, 고양이 상단 780, 속도 난수 배율 1인 경우 `(780+54)/speed`다. 아이템 하단이 `CAT_TOP+34`에 닿는 순간부터 잡히며, 생성 시 하단은 -20이다. 실제 값에는 속도 ±8%, 프레임 간격 등이 영향을 준다.

- 실제 속도 = 스테이지 속도 × 종류 배율 × `CAT_TOP/780` × 0.92~1.08.
- 캔·장화·폭탄은 일반 배율 1, 상어 1.25, 해파리 0.85다. 상어는 생성 후 0.7초, 해파리는 0.6초의 경고 대기가 별도로 있다.
- 한 스테이지는 60초다. 그 안에서 일반 낙하 속도는 올라가지 않고 생성 간격만 진행도에 따라 최대 28% 줄어든다. 생성 간격에도 0.85~1.15배 난수가 있다.
- 피버의 기준 속도는 600/640, 생성 주기는 0.075초이고 추가 생성 확률은 45%다. 후반 일반 속도가 650~750이므로 피버가 언제나 더 빠른 낙하는 아니다.
- 화면 확장은 `84d41b5`, 거리 보정은 바로 뒤 `f0988c0`(2026-10-20)에 추가됐다. 따라서 최신 코드의 보정 누락을 원인으로 단정할 수 없다. 설치된 APK의 코드와 기기 성능은 이번에 확인하지 않았다.

360×800의 예시 뷰포트에서는 논리 높이 1420, 고양이 상단 1176, 속도 배율 약 1.508이다. 1스테이지 생성→판정 시간은 기본 화면 2.527초에서 2.472초로 약간 줄어든다. 보정이 없다면 3.727초다. 현재 보정은 고양이 상단 비율을 사용해 정확히 같은 시간이 되지는 않지만 긴 화면에서 대기가 늘어나는 방향은 아니다.

설계 의견: 초반이 느리다는 체감을 해결하려면 1스테이지 도달 시간을 2.5초에서 2.0~2.2초 정도로 줄이는 안을 먼저 비교할 만하다(약 15~25% 속도 증가). 이는 플레이 검증 전 제안이다. 생성 빈도까지 동시에 크게 올리면 난도와 속도감의 원인을 구별하기 어려워 우선 낙하 속도를 비교하는 것이 좋다. 실제 설치본에서 보정이 적용됐는지 확인하는 일도 필요하다.

현재 구현에 이미 거리 보정이 있다면 보정 누락으로 단정하면 안 된다. 이 경우 실제 기기에서 첫 포획 시간과 화면 대비 이동 비율을 확인한 뒤, 기본 속도나 스테이지 내 가속 곡선을 조정할지 판단해야 한다.
